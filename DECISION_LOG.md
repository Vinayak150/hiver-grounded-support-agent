# Decision log

| ID | Decision | Status | Rationale |
| --- | --- | --- | --- |
| ADR-01 | Build independently rather than importing either reference repository. | Accepted | Assignment integrity requires citations and forbids silent copying. |
| ADR-02 | Treat assignment documents as constraints, not as evidence of dataset results. | Accepted | No unmeasured statistics or claims should enter the report. |
| ADR-03 | Make all data-dependent choices provisional until profiling. | Accepted | Brand, taxonomy, split and retrieval choices require evidence. |
| ADR-04 | Use thread-level isolation for every evaluation partition. | Accepted | Tweet-level splits would leak conversational context. |
| ADR-05 | Fail closed for private, account-specific, security, payment, or weak-evidence cases. | Accepted | Historical data cannot authorize current/account actions. |
| ADR-06 | Defer model, prompt, and threshold decisions. | Pending Phase 1–4 | These need data profiling and development-only calibration. |
| ADR-07 | Require a genuine LLM quality judge plus actual human comparison. | Accepted | A deterministic proxy alone does not satisfy the brief. |
| ADR-08 | Use canonical parent linkage for reconstruction, with child-link fields retained only for consistency checks. | Accepted | A reply has at most one parent; child fields can be plural, absent, or inconsistent. The actual dataset schema will be validated before profiling. |
| ADR-09 | Use SQLite as an ephemeral profiling index rather than loading the full TWCS export into memory. | Accepted | It supports deterministic joins, anomaly checks, and a multi-million-row CSV on ordinary hardware without committing raw data or adding distributed infrastructure. |
| ADR-10 | Select a brand by configured eligibility gates and deterministic, visible tie-breaks—not a hidden composite score. | Accepted | The assignment requires raw evidence and stated trade-offs; selection remains blocked until real data is profiled. |
| ADR-11 | Parse TWCS `created_at` values with the Twitter timestamp format in addition to ISO 8601. | Accepted | The supplied data uses `Tue Oct 31 22:10:47 +0000 2017`; without this parser every timestamp would have been falsely counted as invalid. |
| ADR-12 | Exclude replies containing a clarifying question from the generic/redirect proxy. | Accepted | Manual deterministic samples showed that apology-plus-question responses were public diagnostic engagement, not generic deflection. A regression test protects this distinction. |
| ADR-13 | Select `AmazonHelp` under the initial Phase 1 rule. | Superseded for Phase 2 | Among 101 volume-eligible accounts, the predeclared lexicographic rule selected it with 51,260 reconstructed multi-turn threads, 90.9109% unique normalized replies, and 9.0891% exact duplicate replies. Its weaker 77.7408% public-containment proxy is an explicit trade-off. |
| ADR-14 | Freeze `SpotifyCares` after the Phase 1.5 saturated audit. | Accepted | At 10,500 multi-turn threads it meets the declared 10,000 sufficiency threshold; it has 97.3766% public containment, 2.4662% generic/redirect, and wins all five declared sensitivity configurations. The ID-only manual audit is diagnostic evidence, not a golden set. |
| ADR-15 | Use a nine-intent provisional taxonomy, including `other_or_unclear`. | Accepted | Train-only TF-IDF/KMeans exploration and lexical signals support broad, auditable support categories without pretending unsupervised clusters are gold labels. Definitions, exclusions, and boundary notes are versioned in `configs/taxonomy.yaml`. |
| ADR-16 | Use chronological thread-level splitting rather than the deterministic random comparison. | Accepted | Chronological 70/15/15 better represents deployment drift and keeps whole reconstructed conversations together. The random split is retained only as a manifest comparison. |
| ADR-17 | Remove exact and high-similarity cross-split collisions from later protected splits. | Accepted | Train is kept stable; iterative decontamination removed colliding dev/golden-candidate threads until the independent audit reported zero exact and zero detected near-duplicate pairs under the declared thresholds. |
| ADR-18 | Build a 300-item golden-candidate queue with a 240/60 representative/challenge mix. | Accepted | The deterministic queue balances taxonomy coverage with difficult cases while remaining entirely inside the golden-candidate split and excluding train/dev. |
| ADR-19 | Require explicit human input through a resumable, versioned annotation CLI. | Accepted | Empty, invalid, or duplicate labels fail closed; writes are atomic; finalized labels cannot be synthesized. The committed annotation file remains header-only until humans perform the pilot. |
| ADR-20 | Freeze exactly 200 final evaluation candidates using a 160/40 representative/challenge mix. | Accepted | Topic-stratified deterministic selection balances four temporal bins, lexical diversity, and observable challenge proxies while rejecting internal duplicates and never using model performance. |
| ADR-21 | Store conservative AI suggestions separately with `annotation_source=AI_PROVISIONAL`. | Accepted | Provisional suggestions can reduce later review effort but are not human labels, agreement evidence, or benchmark ground truth; `UNSURE` is retained for low-confidence cases. |
| ADR-22 | Protect the 200 frozen thread IDs from every training/tuning workflow and require typed confirmation in review mode. | Accepted | TRAIN/DEVELOPMENT may support model development, but frozen text and provisional/future human labels cannot enter training, retrieval, prompting, taxonomy tuning, or development selection. |

Future entries will be added only for non-obvious decisions supported by project evidence.
